# 远征检查点：0.3.0-dev

无尽模式的一局可能很长。此前只保存水晶、角色解锁和设置，关闭应用会丢失活着的远征；本轮加入独立局内检查点。

## 玩家流程

- 新远征仍从1级开始。营地有未完成记录时，显示继续按钮及等级、节点、时长；重新开始按钮明确标为放弃已保存远征。
- 活动状态每20秒保存；升级选项出现/选择、节点变化、切后台、正常关闭时也保存。
- 暂停菜单提供保存并返回营地。Android返回键先暂停，再返回营地保存；营地返回键退出应用。
- 重启应用后先到营地。继续时恢复为暂停；如果当时正在选升级，则保留原三个选项并继续选择。
- 死亡提交奖励后清除主检查点、备份和临时文件。新一局不会继承旧等级或装备状态。

定期检查点提供恢复时点；系统在前台直接终止进程且没有生命周期通知时，可能回到最近一次保存的进度，最多约20秒。不能把它描述为每帧持久化。

## 保存边界

保留角色属性、位置、经验与构筑、节点计时、敌人生命/前摇/冲锋、已发射弹体、掉落物、场地阶段、能力冷却，以及战斗和场地随机数状态。呈现资源、窗口状态和手指意图不保存。

检查点是schema v1的Variant数据，读取时不反序列化对象。临时文件写完后替换主文件，保留上一份有效备份；不完整的主文件可退回备份。未知格式或不存在的内容ID不进行部分恢复。

每局使用独立稳定ID。死亡奖励先提交局外记录，再清除检查点；即使提交后删除前进程被回收，启动时也会识别已结算ID并清除旧记录。写入失败不会提前清除恢复数据；再次提交不重复增加奖励。

## 验证

`tests/checkpoint_smoke.gd` 的27项检查覆盖：磁盘往返精确保留向量/颜色/类型数组和64位RNG、敌人与弹体恢复、默认暂停、600步继续轨迹一致、升级不重抽、备份退回、旧格式拒绝、清除备份、奖励去重、提交失败保留、营地继续、新局归1级、定期保存、切后台即时保存、启动过滤已结算记录与重复返回通知合并。

`tools/checkpoint_process_probe.gd` 分别以write/read两个独立进程执行：进程A保存等级2、3秒、待选择升级；进程B恢复同一局ID、同一随机数状态、同一组选项。记录见 `builds/checkpoint-probe/`。

真实GL渲染已检查 `builds/previews/camp-continue.png` 与 `restored-choice.png`，继续按钮和新增菜单在1280×720内完整显示。已有80项回归、空间查询与触控集成检查保持通过。真机仍按用户要求暂缓，安卓行为以电脑模拟器进一步验证。

Android 16模拟器实测发现一次Back会连续导航到退出；[Godot上游报告](https://github.com/godotengine/godot/issues/123454)描述了targetSdk 36的双通知路径。当前对200ms内重复通知只执行一次，独立的下一次按键仍正常工作；不改变系统Home切后台与保存行为。

## 安卓模拟器结果

电脑Android 36模拟器安装0.3.0后：从1级开始，注入独立移动/攻击/技能触点，切后台保存；强制结束进程后重启，检查点SHA256仍为 `fd1e981f36deebcfd1e5b4faaaab96389d210f99047c7c293b66b615eb071332`。继续后显示生命100、等级1、节点1、00:06，角色在原位置、技能剩余冷却5.9秒，保持暂停等待手动继续。

返回键兼容修复后的日志记录一条暂停状态导航，以及17ms后的重复通知被忽略。营地保留继续原角色的入口，应用进程没有退出。截图和日志位于 `builds/checkpoint-probe/`，包括 `android-back-camp.png`、`android-restored-run.png`、检查点前后哈希文本及 `apk-manifest.json`。
