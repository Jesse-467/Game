# 数值配置与策划工作流

数值源文件在 `design/数值策划/`，共六份中文 Excel、36 个页签。面向策划的编辑说明见该目录的 README 和各表“使用说明”。运行时 ID、字段映射和图集信息留在 `design/planner-schema.json`；策划使用中文名称、数字编号、单位及下拉选项。

## 导出和验证

保存表格后在项目根目录执行：

```powershell
python tools/export_balance.py
./tools/run.ps1 -Check
./tools/build-android.ps1
```

导出器读取六份表，校验数值范围、必填字段及跨表引用，再生成 `data/` 下八份 JSON 和 `config-manifest.json`。`--check` 只验证，不修改文件；安卓构建先执行此检查，表与配置不同步时停止打包。清单记录每份 Excel 和运行配置的 SHA256，可与 APK 内实际读取的数据核对。

现有对象可以改数值、名称、顺序、组合、落点和引用。新增对象由开发登记编号、素材和引用选项；新增全新行为还需实现其语义。策划提供设计和中文名称即可。不要改变已有编号以代替创建新对象。

游戏不加载 Excel 或所有未来关卡的实例。`GameplayConfig` 缓存八份小型定义，总计约43KB；进入当前关卡时才按曲线计算所需怪物基础属性。关卡状态随后应用，模板保持不变。需要更多内容时可以按内容包拆分定义；当前不引入无用途的后台服务。

## 计算顺序

装备是基础数值：先合并角色基础和装备，再从祝福层数统一重算，替换不会残留旧加成或治疗角色。

攻击增幅、目标类别增伤、场地、技能、暴击、护甲各有自己的计算阶段。同类祝福增幅相加；各阶段相乘。攻速和冷却速度同样汇总收益。暴击概率扣除怪物暴击抵抗，防御按配置的曲线常数计算减伤。程序常量只保留算法结构、存档迁移和表现布局；可调整的玩法数值由表导出。

怪物的等级、生命、伤害、防御、抗暴击、速度先从模板和成长曲线生成；“关卡状态”中的额外生命/伤害/速度增幅在各自类别内相加，再作用于成长后的基础值。固定防御和抵抗增量单独相加。快照保留基础值和最终值便于排查。

## 临时简单测试配置

`design/profiles/qa-easy.json` 是开发流程测试的独立配置，只有电脑测试工具显式传入 `--qa-easy` 时才在内存中覆盖定义。原始高难文件保持不变。此模式的自动生存和帧率记录仅验证流程与渲染，不用于判断正式难度。

正式入口使用 `release-hard`。安卓导出排除 `design/`、`tools/` 和 `tests/`，不含简单测试配置和测试入口。调试 APK 的启动日志输出实际读取的八份配置散列，用于核对交付数值。

## 自动验证的范围

`tools/check_configuration_pipeline.py` 修改解析后的临时表数据，再调用实际 Godot 计算：玩家生命、装备基础攻击、两层攻击祝福、怪物模板生命、关卡状态和额外防御。测试比较预期值，并验证正式配置文件未变化。它验证实际数值链路；工作簿格式、单位、选择项和布局另外通过渲染复核。
