# 0.7.0 测试反馈改进与交付

本轮对应六条试玩反馈，验收以新 APK 中的实际行为为准。

1. 少量红色生命药剂：击杀掉落，掉落间隔和地面数量受控；满血时保留，贴近拾取，死亡后不会复活。
2. Boss 基础生命、成长和伤害提高，三个血量阶段加入组合攻击与持续危险区域，保留明确预警和躲避路径。
3. 普通怪加入跳扑、侧翼突进、近身重击和远程齐射；精英与后续循环持续增加压力。削减过强的叠乘收益。
4. 每轮的每个场地区域独立选型，同轮不重复；圆形区域保持间距。预警、持续时间和区域美术保持对应。
5. 三个职业各三种主动技能。成长节点提供技能强化或替换，替换保留已训练等级及当前冷却，继续使用一个技能键。
6. 武器、护甲、饰品、靴子四部位，三种品质，拾取时比较后替换；装备每局清空，局外通过击败 Boss 解锁新类型。
7. 最后完成数值配置化：按类型分为六份中文策划 Excel，同类内容按页签组织。表内使用中文名称、单位、百分比和选择项；程序字段、运行时ID和导出映射留在开发工具。覆盖所有角色、装备、祝福、技能、战斗参数、掉落、局外经济、关卡出怪、Boss轮换和成长曲线。构建时校验并导出轻量配置；运行时缓存小型定义并即时计算当前关卡数值，不载入 Excel。怪物加入等级、防御、抗暴击属性。

## 数值规则

用户明确指定：装备提供基础数值，同类 buff 在乘区内加算，不同乘区相乘。

`伤害 = (角色基础攻击 + 装备攻击 + 固定攻击成长) × (1 + 攻击祝福合计) × 分光伤害修正 × (1 + 对应目标增伤合计) × 场地倍率 × 技能倍率 × 暴击倍率`

怪物另有明确计算阶段：先从模板和关卡等级曲线生成基础生命、伤害、防御、抗暴击与移动速度，再应用独立配置的关卡状态。同类状态合计加算，保存基础属性和最终属性用于核对，不修改模板。

装备属性先合并，再统一从原始角色属性和祝福层数重算。替换装备不会把旧属性残留在角色上，也不会通过反复换装获得回血。攻速祝福采用合计攻速收益；冷却成长采用合计冷却速度收益，避免连续乘算。

## 数值与非数值测试分开

用户明确指出自动走位弱于实际玩家，不以自动策略能否长时间存活作为降低正式难度的理由。当前高难数值作为 `release-hard` 保留。

`design/profiles/qa-easy.json` 是临时简易参数。只有电脑 QA 工具显式启用时才在进程内覆盖缓存，原始配置文件保持不变。真实渲染与流程测试可使用该配置；数值测试继续用高难参数。正式入口没有切换简易配置的入口，Android 导出排除设计表、测试配置和 QA 脚本。打包将核对正式配置及 APK 中的数据。

## 高难数值与成长

普通怪基础生命依次为30、22、60、46、62，精英180；三个Boss模板生命为1000、1600、2200。普通怪基础生命每分钟增长18%，每级另加3%；Boss每次登场增加40%、每完整轮换增加115%，每级另加4%。这些增幅用于生成基础生命，再计算本节点的额外状态。首个Boss在节点5为等级3、生命1080；节点20的破城魔像等级14、生命3870。后续数值由曲线即时计算。

怪物基础伤害每分钟增长7.5%、每级另加2.5%，技能伤害使用同一基础成长，再计算关卡状态。防御随等级增加，暴击抵抗扣减玩家有效暴击概率。节点2、3、4分别加入坚甲、狂战、疾行军势，Boss节点增加伤害及抗暴击；状态有独立页签，不混入模板。

保留此前数值探索的报告，最后一组高难骑士模型包含9次自动测试，存活约157–347秒，其中1次在219.1秒击败首次Boss。自动策略能力有限，该结果用于观察压力、掉落和流程，不代表玩家通过率。本轮遵循用户要求保留高难配置，未为自动策略存活而继续降低难度。

## 配置与回归

六份中文策划表包含36个页签，按类型分文件、同类分页。所有页签的标题、单位、选择项和视图已复核；程序字段和运行时ID保存在开发映射文件中。百分比直接以百分数显示，角度使用度，时间使用秒。装备、祝福、技能、玩家基础、怪物、Boss招式/阶段、关卡状态、掉落、营地和成长曲线均从表导出。使用说明见 `design/数值策划/README.md`，开发流程见 `docs/configuration.md`。

Excel导出的八份定义与保留的高难配置逐项一致。实际 Godot 参数变更验证通过：临时改变玩家生命、装备基础攻击、攻击祝福、怪物基础生命及额外关卡状态，实际计算输出相应改变，正式文件保持不变。

十组战斗与UI回归通过316项命名检查，另有500次碰撞查询和真实视口多指升级检查。覆盖乘区内加算、装备替换无残留/回血、药剂间隔/数量/满血/死亡行为、技能强化/替换/等级/冷却、混合场地间距及分布、组合攻击几何、旧档迁移及断点恢复。日志在 `builds/iteration-0.7/full-regression.log`。

## 真实渲染与安卓验证

电脑GL用独立简易配置完成五分钟持续流程测试，共17952个实际绘制帧，平均帧间隔16.71ms，95分位16.9ms，场景更新95分位0.5ms。静态内存采样约73.5–75.1MB，观察到的节点数量46–50。此测试经历17次成长选择、装备替换、一次Boss击败及药剂拾取，达到等级18、节点9；只作为流程和渲染证据。报告 `builds/iteration-0.7/soak-easy.json`。正式高难配置另生成七种实际渲染场景，存放在同目录的 `render/`。

Android36模拟器安装导出的正式高难APK，实际启动日志读取的八份定义散列与构建清单逐项相符。验证使用独立检查点和应用正常UI，未在APK中加入测试场景加载入口。

- 旧v2检查点迁移到v3，节点20魔像生命保持70%，获得当前等级、防御、抗暴击和基础属性记录。
- 装备比较与技能选择在强制结束进程后保持完全相同的画面和原选择。
- 实际装备精良锁甲后，基础生命上限100→118.816，护甲增加12.544；原长剑使基础攻击为15。换装不治疗。移动拾取药剂后生命40→62.75264，符合固定18加最大生命4%的配置。
- 技能替换为圣盾反击1级，保留已学圣光爆发2级；实际三指移动、按住攻击和技能释放通过。检查点保存装备、技能等级及剩余冷却，返回后台暂停。
- 测试完成后，模拟器原有进度和检查点按字节恢复，并关闭本轮模拟器。

模拟器图片、日志、检查点解析及汇总为 `builds/iteration-0.7/android/native-report.json`。上述电脑帧率不代表红米K80性能；用户已明确暂缓真机调试，新难度和可玩性需要人工试玩后继续修订。
