# 电脑渲染与操作验证：0.2.1-dev

范围：在电脑AMD Radeon 780M上，以真实1280×720 GL游戏窗口执行压力测试；不使用headless渲染，不推断K80帧率。使用游戏本身的模拟与表现层，测试场景维持指定数量及高生命敌人，因此是性能夹具，不是难度评估。

## 测量方法

`tools/profile_render.gd` 在每个场景预热2秒、采样8秒。垂直同步仅在测试窗口关闭，帧率上限60；直接监听每次渲染完成，并同时记录引擎实际绘制帧数、实体实际范围、每次场景更新成本和夹具补充成本。

最初包含垂直同步与双信号等待的记录不用于结论，保留为 `initial-uncalibrated.json`。校准后、优化前后的记录分别为 `before-spatial.json` 与 `after-spatial.json`，位于 `builds/reports/render/`。

| 场景 | 优化前平均帧间隔 | 优化后平均帧间隔 | 更新耗时95分位（前→后） |
| --- | --- | --- | --- |
| 常规：约20敌人、28弹体、24特效 | 16.66ms | 16.66ms | 0.923→0.845ms |
| 配置上限：120敌人、240弹体、128特效 | 37.19ms | 16.66ms | 10.418→3.403ms |
| 上限场景暂停 | 16.61ms | 16.66ms | 1.242→1.281ms |

上限场景平均吞吐约27→60FPS，单次更新成本95分位降低约67%。优化后帧间隔95分位21.46ms、最大24.69ms，仍有桌面调度抖动，不把平均60FPS描述为每帧严格16.67ms。

另外启用多弹、贯穿、暴击、爆炸、减速、精英增伤和短技能冷却共同检查上限场景，平均16.66ms、更新95分位3.598ms。该补充运行同时存在后台CPU模型任务，作为额外负载检查，不用于前后性能差异结论；记录为 `full_build_limits.json`。

采样记录包含实际数量：动作场景弹体会命中和过期，特效会消失，不能只把填充目标当作整个采样期间恒定数量。暂停场景保持120/240/128，模拟时间没有推进；活动场景模拟时间推进约8秒。

## 实现与正确性

弹体查询按64像素单元建立敌人中心索引，按最大敌人半径扩大扫掠范围，再使用原有精确碰撞规则。候选按原敌人数组次序排序，保留穿透消耗、击杀、暴击随机数和伤害顺序；没有削减敌人、弹体、特效或机制配置上限。

500条固定种子随机扫掠线段（含负坐标、不同半径、跨多个单元）与全量几何判断核对，未遗漏碰撞；重建后不保留旧索引。9组骑士30分钟模型与此前记录比较，伤害、击杀、经验、构筑、每分钟记录和Boss结果完全一致。

回归增加：升级菜单清空旧意图后，玩家保持按下的手指可用新的拖动重新接管摇杆/攻击；暂停或升级中拖动不移动角色。经过真实视口输入路由验证，右手选择升级时可保持左手触摸，选择后拖动恢复移动。闪避读取本次最新移动意图，避免同帧换向时沿旧方向闪避。

当前回归：34项战斗、29项场地、17项界面；另有空间查询验证和升级触控集成验证。命令 `./tools/run.ps1 -Check` 覆盖上述项目。

## 安卓模拟器构建核对

最终APK为0.2.1-dev、versionCode 3，含arm64-v8a与x86_64。安装到电脑Android 36模拟器后，设备内APK与交付文件SHA256相同（`f0b615721105999f2017dfd3514ed354d9cb00efe1f75467e2a6c258c7d6b327`）。确认进入Godot主循环，触控探针再次完成独立移动、按住攻击与技能输入，没有发现脚本错误。

证据为 `builds/reports/render/android-touch-probe.log`、`android-0-2-1.png` 与 `apk-manifest.json`。此项验证新碰撞模块能够在Android实际运行，渲染性能数字仍来自前述电脑GL测试。
